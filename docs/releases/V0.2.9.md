# CineRelay v0.2.9 — First consolidated cinematic stable release

This release consolidates the approved CineRelay Android editorial experience and reliability improvements from the full v2.0–v2.5 development cycle.

## What’s new

- **Home:** cinematic ten-story slideshow sourced from genuinely recent YouTube updates, with automatic progression every five seconds, manual swiping, original artwork fallbacks, and independent Web news discovery rails.
- **Faster navigation:** preserves Home’s prepared content and scroll position on trips to OTT, Radar and back; uses cached stories and lets YouTube updates display before Web feeds finish.
- **OTT:** artwork-first release shelves, a compact Refine button next to Refresh, evidence-aware filters, and clearer release dates and details.
- **Today in Cinema:** improved cinema-history spotlight and poster layouts, with locally rendered original artwork when a real poster is missing.
- **Radar:** preserves the previously approved experience.
- **Reliability:** fixes stale account and session data, delayed detail responses, duplicate loads, notification setup caching, and Archive/Sources state isolation.

## Data, privacy and artwork

CineRelay uses original abstract fallback designs in place of missing art. These are not represented as official film posters. End-user sessions and favorites are separate from shared source/news/OTT information. This release does not contain destructive database migrations.

## Quality and scope

The S4 release candidate passed unit tests, signed release build checks, an Android 35 emulator startup smoke test, and an in-place upgrade from the S3 release candidate. Real-device and production connectivity can vary; report any remaining notification delivery or account-switch issues for a subsequent bugfix release.

## Rollback

For audit and recovery, retain the last known-good S3 `0.2.9-rc.1` and S4 `0.2.9` signed artifacts, as well as the release tag and commit. Android does not support installing a lower version code over a higher one without a separate upgrade build; rollback may require reissuing older source code with a **higher** version code, not downgrading in place.
