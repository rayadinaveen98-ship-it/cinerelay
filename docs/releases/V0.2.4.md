# CineRelay v0.2.4

CineRelay v0.2.4 is a consumer-quality and performance pass focused on making Home feel immediate, making Indian cinema easier to discover, and making OTT/history surfaces easier to understand.

## Highlights

- Home can render the last successful feed immediately from a per-user persistent cache while a fresh feed refreshes in the background.
- Home YouTube and Web feeds load concurrently with smaller, focused payloads to reduce startup work.
- Startup no longer blocks the main Home surface while personalization and notification setup are still resolving.
- Home ranking now gives explicit weight to the user's preferred languages, Indian cinema languages, verified/official signals, and multi-source stories while reducing generic music-label updates from dominating the hero.
- Adds an Indian Cinema Home rail and simplifies language rail names such as Telugu Cinema and Hindi Cinema.
- Reduces the Home Archive control to a single icon button.
- Newsroom language metadata now falls back from the raw item to the canonical entity language and then the source's declared language, fixing many missing-language cases.
- Today in Cinema now requests the user's preferred language in parallel with the general history feed, putting Telugu/other preferred-language titles first while retaining the wider history.
- Simplifies Today and OTT copy so internal verification terminology is less visible to consumers.
- OTT Today, Upcoming, and Released windows load concurrently.
- Refines OTT release cards with wrapping metadata chips, more stable source/verification alignment, wider cards, and shorter empty states.
- Keeps the existing trusted source registry and X-dormant boundary unchanged.

## Release integrity

- Package: `com.cinerelay.app`
- Version: `0.2.4`
- Version code: `210004`
- Stable build type: Android `release` with minification and resource shrinking enabled.
- Firebase configuration is mandatory for stable publication.
- Permanent CineRelay signer is mandatory and verified against the repository-pinned certificate digest.
- Privileged server credential markers are scanned from source and the final APK before publication.
- v0.2.3 remains immutable.

## Data boundaries

- Language fallback is descriptive only: raw item language remains preferred, followed by canonical entity language, then the source's declared language.
- Today history still uses the existing history provider; v0.2.4 improves language coverage at the client layer rather than inventing unverified historical release dates.
- WebSub remains an accelerator; authoritative fallback ingestion remains unchanged.
- X remains intentionally dormant.
